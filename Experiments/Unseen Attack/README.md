# Evilog — Unseen Attack Experiment (CRLF)

In addition to the seven application-layer attacks that Evilog defends against, this
experiment also attempts **CRLF/HTTP header injection** to show how an attack that is not
defined in the detector's taxonomy gets concealed.

## Background (Motivation)

When user input resides in the login email field, the detector reliably detects attacks.
However, when attacks are placed in an **HTTP header (Referer)**, whose values are naturally
diverse, the detector's judgment can weaken. Motivated by this, we placed various attacks in
the header and found that, while most attacks were still detected, **CRLF/HTTP header
injection was concealed because it is not defined in the detector's taxonomy.** This
experiment reproduces that phenomenon.

> **Terminology:** In the code, the defense implemented as `DetectThenMaskShieldV2`
> (in `a2_fix_reattack.py`) corresponds to **Evilog** in the paper. The original defense
> file names are kept unchanged.

## 3. Setup with the Original Artifact

This experiment reuses the original defense code, so you need the original artifact
(`aiops_blindness_artifact`). The simplest way to run:

1. Download the original artifact (`aiops_blindness_artifact`), which contains `harness/` and
   `demo_target/`.
2. Copy `unseen_crlf_all7.py` from this folder into `aiops_blindness_artifact/harness/`,
   so it sits next to `a2_fix_reattack.py`, `detect_then_mask.py`, and `live_anchor.py`.
3. Obtain **AIOpsShield** (from [1]) and set `AIOPSSHIELD_PATH` to its path.

### Run the app (required for this experiment)
Unlike the other experiments, this one learns the masking templates directly from the app,
so you must **first run the `demo_target` app** from the artifact:
```bash
python aiops_blindness_artifact/demo_target/app.py --host 127.0.0.1 --port 8091
```

## 4. Run the Experiment
```bash
python -u unseen_crlf_all7.py 2>&1 | tee results/run_crlf.txt
```

**Result:** The seven application-layer attacks (SQL injection, command injection, XSS,
Log4Shell, NoSQL, LDAP, SSTI) are defined in the detector's taxonomy and are mostly detected,
whereas **CRLF is absent from the taxonomy, so it is classified as benign, leaves no memo,
and is concealed from the final agent.**

> **Reproducibility note:** Attack payloads are regenerated by an LLM on each run
> (`temperature=0.9`), so exact numbers may vary, but the trend—**the 7 attacks are detected
> while CRLF is concealed**—reproduces consistently.

## 5. Mitigating CRLF — Add One Line to the Detector Taxonomy

The CRLF miss occurs because CRLF is not in the detector-prompt's attack-type list (taxonomy).
**Without creating a separate defense file**, a one-line edit to the original defense file
handles it.

- **File:** `a2_fix_reattack.py`
- **Location:** inside the detector-prompt variable `_DET_SYS_V2`, on the line listing attack types

**Before:**
```python
"command injection, Log4Shell, SSRF, path traversal, NoSQL/LDAP injection, SSTI, etc.), you MUST reply "
```

**After — add `CRLF / HTTP header injection,`:**
```python
"command injection, Log4Shell, SSRF, path traversal, NoSQL/LDAP injection, SSTI, CRLF / HTTP header injection, etc.), you MUST reply "
```

Once CRLF is listed in the taxonomy, the detector classifies it as an attack, leaves a memo,
and the final agent can detect it. Note that this is a partial fix that relies on an
enumerated list; for a more fundamental approach to attacks absent from the list, see the
Discussion in the paper.

The following come from the **original artifact** (`aiops_blindness_artifact`) and are **not**
duplicated here. Copy `unseen_crlf_all7.py` into `aiops_blindness_artifact/harness/`

- `AIOpsShield` : the existing masking defense from [1]. It is **not redistributed** (its
  released code has no license). Obtain it from the base paper's official release and set
  `AIOPSSHIELD_PATH`, as described in the original artifact's `THIRD_PARTY.md`.
