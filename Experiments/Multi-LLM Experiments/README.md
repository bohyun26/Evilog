# Evilog: Evidence-Preserving Log Sanitization for LLM-based AIOps Agents

Reproduction code for the paper proposing **Evilog**, a defense that mitigates the problem
where log masking for prompt-injection defense also removes the evidence of application-layer
attacks, thereby degrading the diagnosis of an AIOps agent.

> **Terminology:** In the code, the defense is the class `DetectThenMaskShieldV2`
> (in `evilog.py`); this is **Evilog** in the paper. The class name is kept as-is to match
> the base artifact it is imported from.

## 3. Setup with the Original Artifact

These scripts reuse the original defense code, so you need the original artifact
(`aiops_blindness_artifact`). The simplest way to run:

1. Download the original artifact repository (`aiops_blindness_artifact`), which contains
   `harness/` and `demo_target/`.
2. Copy the `.py` files (and `.mask_templates.jsonl`) from this folder into
   `aiops_blindness_artifact/harness/`, so they sit next to `evilog.py`,
   `detect_then_mask.py`, and `live_anchor.py`.
3. Obtain **AIOpsShield** (from [1]) and set `AIOPSSHIELD_PATH` to its path.
4. Run the scripts from inside `harness/`.

> The `.mask_templates.jsonl` cache is included, so you do **not** need to run the app for
> these experiments. (The app is only needed if the cache is missing.)

## 4. Experiment 1 — Detection Rate by Final Agent (Table III)
The same attacks (~920 variants of 7 application-layer attack types) are passed through the
three conditions—**No Defense / AIOpsShield / Evilog**—and the diagnoses produced by
GPT-4o, Gemini, and Claude are compared.

```bash
python -u defense_paired_gpt4o_7.py   2>&1 | tee results/run_gpt7.txt
python -u defense_paired_gemini_7.py  2>&1 | tee results/run_gemini7.txt
python -u defense_paired_claude_7.py  2>&1 | tee results/run_claude7.txt
```

**Results (the "overall detection rate" at the end of each log):**

| Final Model | No Defense | AIOpsShield | Evilog |
|---|---|---|---|
| GPT-4o | 89.6% | 36.1% | 97.6% |
| Gemini 2.5 Flash | 92.9% | 6.5% | 92.6% |
| Claude Sonnet | 99.6% | 55.2% | 96.8% |

→ For all three models, detection drops sharply under AIOpsShield (concealment) but
recovers and converges to 92%+ under Evilog.

> **Reproducibility note:** Attack payloads are regenerated by an LLM on each run
> (`temperature=0.9`), so exact numbers may vary by a few percentage points. However, the
> trend—**high without defense → sharp drop under AIOpsShield → recovery/convergence under
> Evilog**—reproduces consistently. The logs in `results/` are the authors' actual runs.

### Analysis — why the rates differ and converge

- **Why Evilog converges across models.** Evilog's detection relies on the **memo the detector
  leaves on the raw field before masking**, not on each final model's own reasoning. Once the
  memo is present, any final agent simply reads it, so the rate stays consistent (92%+)
  regardless of which model is the final agent. (Detector false-positive rate: **0%** for all
  three — see Experiment 2.)
- **Why AIOpsShield varies so much by model.** Under masking the evidence is gone, so detection
  falls back on each model's own inference tendency. Claude leans conservative / safety-oriented
  and flags threats even with scarce evidence (highest under both No Defense and AIOpsShield);
  GPT-4o reflects clear evidence faithfully but is weaker when it must self-infer (lower under
  masking, yet highest under Evilog, where the memo is supplied); Gemini interprets input
  literally, so once the original text is masked its inference-based detection is the lowest (6.5%).
- **Why Evilog is not 100% (miss patterns).** Misses differ by model: GPT-4o — 6 SSTI + 2 NoSQL;
  Claude — 6 SSTI + 2 LDAP; Gemini — spread across types, incl. 11 XSS. Two-stage explanation:
  (1) SSTI / LDAP / XSS payloads are structurally similar to benign input, so the detector
  misclassifies them as benign and leaves no memo; (2) without a memo, detection falls back on
  the final agent's reasoning — GPT-4o and Claude recover all but SSTI, while Gemini cannot
  recover and misses across several types. Attacks with distinctive forms (SQL injection,
  command injection, Log4Shell) are reliably caught by the detector, so all three models reach
  **≥99%**. In short, Evilog's ceiling is set by the **detector's judgment**.

## 5. Experiment 2 — Detector False-Positive Rate (FP)
Measures whether the detector misjudges benign inputs (120 samples) as attacks.

```bash
python -u fp_evilog.py
```
**Result:** Evilog's detector (GPT-4o-mini) records a **0% false-positive rate** over 120
benign inputs (i.e., it achieves attack detection without misclassifying benign input).
This matches the detector false-positive rate reported in the paper (0%). The script prints
the rate to the console; redirect it to a file (e.g. `| tee results/run_fp.txt`) if you want
to keep the log.

> **Reproducibility note:** Benign inputs are also regenerated on each run, but the result
> that Evilog's detector does not misjudge benign input as attacks reproduces consistently.

The following come from the **original artifact** (`aiops_blindness_artifact`) and are **not**

- `aiops_blindness_artifact/harness/live_anchor.py` : canary / masking-template learning

  released code has no license). Obtain it from the base paper's official release and set
  `AIOPSSHIELD_PATH`, as described in the original artifact's `THIRD_PARTY.md`.
